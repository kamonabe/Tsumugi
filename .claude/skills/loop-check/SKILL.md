# Tsumugi 開発ループ: 確認モードの入口

このスキルは、確認モードで **何をどの順に読むか** と、**拾うものがあるかの機械的な判定** だけを持つ。
何をどう処理するかの正本は [`docs/loop-runbook.md`](../../../docs/loop-runbook.md)（以下「手順書」）であり、ここには規則を書き写さない。
手順書とこのスキルが食い違ったら手順書に従い、終わったあとで報告に「loop-check スキルが手順書と食い違っていた」と書く。

以下のパスは、手順書 §2 のとおり clone したリポジトリ（`develop/tsumugi`）からの相対パスである。

## 1. 準備

1. 手順書 §2 のとおり kanade と Tsumugi を clone する。**この時点では、ほかの文書はまだ読まない。**
2. 開始時刻を控える（上限は手順書 §11.2: 15 分、再レビューを行う回は 45 分）。
3. `gh api user --jq .login` で認証中のアカウントを確かめる。`kamonabe1927-stack` でなければ、手順書 §2 のとおり GitHub に何も書き込まずに `#tsumugi-dev` へ報告して終了する。

## 2. 拾うものを判定する（文書を読む前に）

```bash
python3 .claude/skills/loop-check/scripts/pickup.py
```

GitHub の REST API だけを読み、手順書 §6.1 の拾うもの・§6.4 の自動マージの候補・§4.1 の残った目印を JSON で出す。
取りこぼしを避けるよう、迷う場合は「有り」に倒してある。

- **終了コードが 0 でない、または出力が JSON として読めない**: 判定できなかったので、3 に進む。
- **`nothing_to_do` が `true`**: 手順書 §6.1 の「どれも無ければ何も書き込まずにすぐ終了する」に当たる。
  GitHub にも Slack にも書き込まず、ほかの文書も読まずに終了する。
- **`found` は空で、`slack_threads_to_read` だけがある**: 判断待ちのスレッドに新しい返信があるかだけを確かめる。
  1. `python3 .claude/skills/loop-check/scripts/runbook_sections.py 3` で手順書 §3（Slack の書き込みの見分け方を含む）だけを読む。
  2. 各リンクのスレッドを Slack の `slack_read_thread` で読む（チャンネル `C0CB1H2HHJB`。リンク末尾の `p1793144318433259` は `ts` の `1793144318.433259`）。
  3. 次のどちらかに当たれば 3 に進む。どちらにも当たらなければ、何も書き込まずに終了する。
     - kamonabe の返信（§3.1 のエージェントの投稿を除く）のうち、その `ts` が項目の `referenced_ts` に無いものがある
       （`referenced_ts` は、エージェントが GitHub に転記した Slack の ts の一覧。転記されていない返信は未処理とみなす）
     - `over_2h` が `true` の項目がある（2 時間返信の無い判断待ち、§7.5）
- **それ以外（`found` に何かある）**: 3 に進む。

## 3. 拾うものがあるとき

1. 手順書 §2 の「そのうえで、次を読んでから作業を始める」の文書（kanade の steering、tsumugi の `CLAUDE.md`、documentation-guide、`slices.toml`）を読む。
2. 手順書の確認に要る節だけを読む。

   ```bash
   python3 .claude/skills/loop-check/scripts/runbook_sections.py 3 4 5 6 7 8.1 10 11
   ```

   再レビュー（§6.5）・修正依頼への対応・判断の反映で PR を直すときは、レビューと直し方の基準として `8 9 14` も読む。
   `loop:drift` issue の判断待ちを反映するときは `13` も読む（§13.2 の記録の仕方）。
   スクリプトが「見つからない節」と出したら、節の番号が変わっているので手順書全体を読む。
3. 手順書 §6.2 の順番どおりに処理する。`pickup.py` の結果は候補の一覧であり、処理するかどうかは手順書の条件で改めて確かめる
   （例: 自動マージは CI・変更したファイル・マージ可能かを §6.4 のとおりに確かめる）。

## スクリプトを直すとき

- `pickup.py` の判定は手順書 §3.1・§4.1・§5・§6.1・§6.4・§6.5・§7・§8.1・§14.4 を機械化したものである。これらの節を変える PR では、同じ PR で `pickup.py` と試験も直す。
- 試験: `python3 -m unittest discover -s .claude/skills/loop-check/scripts`（CI の `loop-scripts` でも走る）
- このスキルとスクリプトはループの規則のファイルであり、変える PR は手順書 §6.3 の承認コメントでしかマージしない（§6.4 の 2）。
