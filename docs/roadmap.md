## 検討事項: 実行安全性（ステップ予算）

### 背景

Tsumugi は現状「閉じた世界」で動く言語（外部I/Oなし）のためセキュリティリスクは低い。
ただし、将来ファイルI/O やネットワーク機能を追加した場合、信頼できないコードの実行や暴走を防ぐ仕組みが必要になる可能性がある。

### 案: ループ反復 + 関数呼び出しのカウント制限

- while / for がループ先頭に戻るタイミングでカウント +1
- 関数呼び出し時にカウント +1
- ループ内の let / if / 代入はカウントしない
- 上限（例: 1,000,000）に達したら強制停止

### この方式の利点

- ユーザーの感覚と一致する（「100万回ループしたら止まる」はわかりやすい）
- ループ内の処理量に左右されない（if が何段あってもカウントに影響しない）
- 書き方に制約を加えない（while true も書ける。止まるなら止まる）
- 無限再帰も検知できる

### 未決定事項

- 上限値の決定（利用シーンに依存。将来ファイルI/O等が入ると大量データ処理で上限に達するケースが出る）
- ユーザーによる上限変更手段の要否（`#!max_steps 5000000` のようなディレクティブ）
- 全文カウント vs ループ+関数呼び出しのみカウント — 後者の方がユーザーにとって予測しやすい
- 実装タイミング — 外部I/O機能の追加が決まってからでも遅くない
